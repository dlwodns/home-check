## 1. 한 줄 소개

**관심 있는 방 하나**를 담으면, ① 그 방이 안전한지 확인하고 ② 그 방에 맞는 계약 방법을 알려 주는 웹 앱입니다. 등기부등본을 올리면 위험 신호를 쉬운 말로 설명하고, 이 방이라면 **누구에게 무엇을 묻고, 계약서에 무엇을 넣을지**까지 알려 줍니다. 계약 과정 6단계는 방마다 진행 표시로 따라갑니다.

일반적인 계약 방법 안내는 블로그 · 정부 안내문에도 많습니다. 홈체크는 **"이 방"에 맞춘** 점검과 계약 방법에 집중합니다.

**형태**: 모바일 우선 웹 + PWA (설치 없이 링크로 바로 열고, 원하면 홈 화면에 아이콘 추가). 앱스토어 앱은 만들지 않음. 휴대폰 화면 기준으로 설계하고 PC에서도 깨지지 않게 함(PC에서는 가운데 휴대폰 폭). 개인 과제는 시연 없이 포스터로 평가.

## 2. 문제

### 이 사람을 돕습니다 (주 타깃)

> **20살 대학 예비 입학생.** 타지역 대학에 붙어서 처음으로 혼자 집을 계약해야 한다. 학교 근처 월세 원룸을 찾는 중이다. 보증금은 부모님이 보태 주신다. 집을 자주 보러 갈 수 없고, 근저당 · 확정일자 · 전입신고 같은 말은 처음 듣는다. **"뭐부터 해야 할지 아무것도 모르겠다."**

### 이 사람이 겪는 어려움

| 어려움 | 결과 |
| --- | --- |
| 무엇을 어떤 순서로 해야 하는지 모름 | 성수기(12월부터 2월)에 급하게 계약하다 확인 단계를 건너뜀 |
| 등기부등본 · 건축물대장을 읽을 줄 모름 | 집주인 확인, 빚(근저당) 확인을 하지 못함 |
| "중개사가 있으니 괜찮겠지"라고 생각함 | 직접 확인해야 할 것을 중개사에게 맡겨 버림 |
| 직거래로 중개수수료를 아끼려 함 | 집주인 본인 확인 같은 보호 절차가 빠짐 |
| 위험하다는 말을 들어도 무엇을 해야 할지 모름 | 그냥 계약하거나, 막연히 불안해함 |

### 근거 (실제 사례)

- 익산: 원룸 임대업자가 대학생 등 임차인 122명의 보증금 약 47억 원을 가로챔 (뉴시스, 2019)
- 전주: 방 13개 다세대주택을 36개로 불법으로 쪼개 대학생 세입자에게 세를 놓음 (전북일보, 2023)
- 인터넷 카페 직거래로 20대 대학생 · 사회초년생 7명이 사기 피해. 경찰은 등기부등본으로 실제 소유주와 계약자가 같은지 확인하라고 당부함 (매일신문, 2024)

## 3. 타깃

기획 의도는 **20살 첫 집계약을 돕는 것**이고, 제품은 **처음이든 또 구하든 집을 구하는 누구나** 쓸 수 있게 만든다 (11/13 결정).

| 구분 | 누구 | 홈체크에서 |
| --- | --- | --- |
| **대표 사례 (설계 기준)** | 타지역 대학에 입학하는 20살, 첫 계약 (위 인물) | 화면 흐름 · 문구 판단 기준, 발표 · 포스터 이야기 |
| **확장 ① 첫 집 누구나** | 나이와 상관없이 처음 집을 구하는 사람 (사회초년생, 첫 독립 등) | **"처음이에요"**: 1단계부터 하나씩. 학생 · 부모님 전용 문구를 쓰지 않고, 해당 없을 수 있는 항목(기숙사 · 사택, 가족과 상의)은 '건너뛰어도 돼요'로 표시하고 진행률에서 불리하지 않게 함 |
| **확장 ② 또 구하는 누구나** | 계약을 해 본 사람 (이사, 재계약) | **"해 봤어요"**: '등기부등본 바로 점검하기'를 맨 위에, 1–3단계는 건너뛰어도 되는 단계로 접고 4단계부터 '지금 할 차례' |

**문구 원칙**: "부모님" 대신 "가족 · 지인 · 함께 보증금을 마련한 사람", "학교 근처" 대신 "학교 · 회사 근처"처럼 대표 사례를 포함하되 다른 사람을 빼지 않는 말을 쓴다.

## 4. 기존 서비스와 차별점

| 서비스 | 하는 일 | 빈 곳 |
| --- | --- | --- |
| 직방 · 다방 · 피터팬 · 네이버 부동산 | 방 찾기 (직방은 AI 진단 기능도 있음) | 방을 고른 **뒤 무엇을 할지**는 안내하지 않음 |
| HUG 안심전세 앱 (공공) | 주소로 위험 진단, 집주인 체납 · 사고 이력, 시세 | **전세** 중심이고 기능이 많아 초보자가 어디부터 볼지 모름 |
| 서울시 · 경기도 AI 진단, 홈큐, 세이프홈즈 | 전세 위험 분석 | **확인할 줄 아는 사람**을 위한 판정 도구 |

*2026년 기능은 언론 보도 기준 (S10)*

**홈체크의 차별점**

1. **내가 고른 방 하나에 맞춘 점검과 계약 방법**: "등기부등본을 확인하세요"가 아니라 "이 방은 근저당 비율이 76%라서 잔금일까지 줄이는 특약을 넣으세요"
2. **대학가 월세 원룸 · 직거래에 특화**: 다가구 원룸의 앞선 세입자 보증금, 불법 개조, 직거래 본인 확인
3. **판정에서 끝나지 않고 다음 행동까지**: 중개사 · 집주인에게 물어볼 질문, 특약 문장 예시, 가족에게 보낼 요약
4. **방마다 계약 완료까지의 길잡이**: 지금 몇 단계인지, 끝(계약 완료 · 보증금 지키기)까지 무엇이 남았는지

기존 서비스와 경쟁하지 않고 **연결**합니다. (예: "이 단계에서는 HUG 안심전세 앱으로 집주인 체납 이력을 확인하세요")

**방 검색은 직접 만들지 않습니다.** 공개된 매물 API가 없고, 방 찾기 앱의 데이터를 긁어 오는 것은 이용약관 · 법적 문제가 있으며, 큰 앱들과 정면으로 겹쳐 홈체크의 위치가 흐려지기 때문입니다. 대신 어디서 찾았든 그 방을 3칸(주소 · 보증금/월세 · 링크 메모)으로 담는 **내 후보 방(F4)**이 홈체크의 시작점입니다.

## 5. 기능

중심은 **F4 내 후보 방**입니다. 방 하나에 F2 점검 → F3 다음 행동 → F1 단계 진행이 붙고, F6 동네 시세는 방 주소로 붙습니다. 기반 기능은 F0 로그인(이메일), 포스터 뒤 기능은 F5 도우미입니다.

### F4. 내 후보 방 (중심 기능, 11-16 결정)

- **홈 = 내 후보 방 목록**. 방 카드마다 점검 결과(신호등) · 확인할 것 개수 · 6단계 진행 막대
- **등록은 3칸**: 주소 · 보증금/월세 · (선택) 매물 링크 · 메모. 링크는 다시 열어 보는 바로가기로만 저장하고, 다른 앱의 매물 정보를 자동으로 가져오지 않음 (공개 API 없음 · 약관 문제)
- **방 상세 순서**
  1. 이 방, 안전한가요? → F2 점검 결과 + F6 동네 시세(참고)
  2. 이 방은 이렇게 계약해요 → F3, 이 방의 판정에 맞춘 할 일 · 질문 · 특약
  3. 계약 과정 → F1 진행 표시, 끝에 "계약 완료 · 보증금 지키기" 도착점
- 저장: 로그인 전에는 이 기기(브라우저)에, 로그인하면 계정에. 주소 · 금액 · 메모 · 체크 상태 · 판정 요약만 저장하고 등기부등본 원문 · 집주인 이름은 저장하지 않음
- 시작 전 튜토리얼 화면은 두지 않음. 전체 과정은 방 상세의 진행 표시로 보여 줌 (IDEAS 11-16)
- **처음 온 사람에게만 로비**(무엇을 하는 앱인지 한 화면), 다시 온 사람은 홈 맨 위 **'이어하기'** 카드(지난번 본 방 · 다음 할 일)
- 방 상세에 함께 붙는 것: **서류 · 준비물**(언제 · 누가 무엇을 챙길지, 법령으로 확인한 비용 · 기한), **혼자 판단하기 어려우면 물어보세요**(대한법률구조공단 132 · HUG 1533-8119, 무료), 계약을 마치면 완료 카드 한 번
- 실제 서류로 점검하면 4단계 '등기부등본 점검하기'가 자동으로 체크됨. **샘플로 해 본 결과는 방에 저장하지 않음**(가짜 판정이 실제 방에 남지 않게)

### F1. 계약 단계 길잡이

- 시작 화면: **처음이에요 / 해 봤어요**
- 첫 질문: **"이 방, 어디서 찾았어요?"** → 공인중개사를 통해서 / 집주인과 직접(직거래)
- 6단계 체크리스트. 항목마다 "왜 중요해요?" 한 줄 설명과 **"근거 보기" 링크**(SOURCES 번호 → 공식 확인 링크)를 붙임
- **용어 한 줄 설명**: 근저당 · 확정일자 · 전입신고 · 특약 같은 용어에 점선 밑줄 → 누르면 한 줄 설명. 설명은 **용어 사전 파일 하나**에 모아 모든 화면 · 결과 설명 · 도우미가 같이 씀 (예: 근저당 = "집주인이 이 집을 담보로 잡히고 빌린 돈이에요. 집이 경매로 넘어가면 이 돈부터 갚아요.")

| 단계 | 내용 |
| --- | --- |
| 1. 준비 | 예산, 부모님과 상의, 기숙사 결과 확인 |
| 2. 집 찾기 | 학교 근처 시세, 방 찾기 앱, 중개사무소 찾기 |
| 3. 집 보러 가기 | 현장 체크리스트 (수압, 곰팡이, 보안, 소음 등) |
| 4. 계약 전 서류 확인 ★ | 등기부등본 · 건축물대장 확인 → **F2로 연결**. 다가구 원룸은 앞선 세입자 보증금 확인 (S5, S6, S7) |
| 5. 계약하는 날 | 계약서 확인, 특약, 보증금 입금 계좌 확인 |
| 6. 입주 후 | 전입신고(14일 이내), 확정일자 (S9) |

**분기별 체크리스트**

- **공인중개사를 통해서**
  1. 등록된 중개사무소인지 조회 (S3)
  2. 상대가 공인중개사인지, 중개보조원인지 확인 (S1, S2, S3)
  3. 중개대상물 확인 · 설명서 받기
  4. 공제증서 사본 받기
  5. 등기부등본을 계약 당일 직접 다시 발급 → F2
  6. 중개수수료 상한 확인 (S4, 지역 조례 확인)
- **집주인과 직접(직거래)**
  1. 계약하러 온 사람이 등기부등본의 소유자와 같은지 신분증으로 확인 (S11)
  2. 보증금 입금 계좌가 소유자 본인 명의인지 확인 (S11)
  3. 대리인이면 위임장 · 인감증명서 확인 (S11)
  4. 등기부등본 · 건축물대장 직접 발급 → F2
  5. 표준 임대차계약서 사용

### F2. 등기부등본 점검

1. 사용자가 등기부등본을 올림 (글자 붙여 넣기 또는 글자가 들어 있는 PDF, 10MB까지. PDF 글자 추출은 **브라우저 안에서만**, 외부 AI 사용 안 함). 등기부가 없는 사람에게는 인터넷등기소에서 떼는 법(열람 700원)을 안내하고, 샘플 3종(안전 · 주의 · 위험)으로 먼저 해 볼 수 있음
2. **규칙 기반 읽기**: 표제부 · 갑구 · 을구의 정해진 구조를 패턴으로 읽어 소유자, 근저당(채권최고액), 말소 여부, 압류 · 가압류, 최근 소유권 이전을 뽑음
   - 읽어 낸 값은 화면에서 사용자가 확인 · 수정 (못 읽은 칸은 "직접 입력해 주세요"로 표시)
   - `samples/expected.json`의 `read` 값과 똑같이 나오는지 자동 테스트
3. **판정은 규칙으로** (기준값 · 문구 · 근거는 `data/judge.json`):
   - 위험: 계약 상대 ≠ 현재 소유자(예전 소유자면 따로 알림), 압류 · 가압류(S12), 가처분 · 가등기 · 경매개시결정(S12), 신탁(S13), 말소되지 않은 임차권등기(S14), 비율 80% 이상
   - 주의: 비율 70% 이상, 시세를 몰라 비율 계산 불가, **앞선 세입자 보증금을 모름**, 공동 소유, 먼저 설정된 전세권(전세금을 빚처럼 계산), **등기부등본에 못 읽은 칸이 있음**(못 읽은 값을 0이나 '문제없음'으로 치지 않음 → 이 경우 '안전'은 절대 나오지 않음)
   - 참고(등급에 영향 없음): 최근 6개월 안 소유권 이전(S16, 법정 기준 아님), 말소된 임차권등기 기록, 계약 상대 이름 미입력
   - 비율 = (채권최고액 + 앞선 보증금 + 내 보증금) ÷ 시세. 소액임차인 최우선변제금(S15)은 판정이 아니라 결과 설명에 씀
   - 70% · 80%는 **법정 기준이 아니라 많이 쓰는 참고선**(S8). 화면에 그대로 밝히고, 공식 진단은 HUG 안심전세 앱으로 연결
4. **쉬운 말 설명**: 판정 결과마다 미리 써 둔 문장 틀 + 용어 사전으로 20살이 이해할 말로 풀어 줌 (같은 서류면 항상 같은 설명)
5. **결과 화면 구성**: 신호등(모양 ▲ ● ✓ + 글자) → 큰 제목(위험이면 '이대로 계약하면 위험해요 · 확인할 것 N가지') → **3줄 요약**(가장 먼저 · 지금 할 일 · 괜찮은 점과 알 수 없는 것 수) → 확인할 것(무슨 뜻 · 왜 위험 · 할 일, 근거 번호) → 비율 막대(시세 ±10% 범위) → 괜찮은 점(초록) → **등기부로는 알 수 없는 것**(늘 표시) → 읽은 내용 확인 · 고치기('내가 고친 값' 표시)
6. **'안전'의 뜻**: '확인한 범위 안에서는 큰 위험 신호가 없어요'. 못 읽은 칸 · 모르는 값이 있으면 안전을 내지 않음

### F0. 로그인 · 진행 저장 (기반 기능)

- **로그인 없이 둘러보기** → 진행 상황을 저장하려면 로그인. 처음 온 20살이 가입 벽에 막히지 않게 함
- 로그인 방식: **이메일 + 비밀번호 (11/13 확정)**. Supabase Auth 사용. **가입 확인 메일 · 비밀번호 찾기는 넣지 않음(11/17 확정)**: 기본 메일은 본인 계정에게만 가고, 무료 Gmail 연결은 스팸함 문제가 남아 가입이 막힌 것처럼 보일 수 있음 → 아래 '실제 서비스로 갈 때 바꿀 것'으로. 보완: 비밀번호 두 번 입력, 이메일 주소 한 번 더 확인, '잊으면 계정에 다시 못 들어와요(이 기기 기록은 남아요)' 안내, 계정 기록 · 계정 지우기. 비밀번호 8자 이상. 받는 개인정보는 이메일만("이메일은 로그인에만 써요" 안내). 카카오 · Google 로그인은 만들지 않음(확장 방향)
- 저장하는 것: 단계별 체크 상태, 점검 결과 **요약**(안전 · 주의 · 위험과 이유)
- **저장하지 않는 것**: 등기부등본 원문, 집주인 이름 등 다른 사람의 개인정보
- 휴대폰과 PC 어디서 열어도 이어서 진행 가능

### F5. 홈체크 도우미 (자주 묻는 질문) — 만들지 않음, 다음 단계

- 화면 아래 **"막히면 물어보세요"** 버튼 → 도우미 창
- AI 대화 대신 **지금 단계에 맞춘 자주 묻는 질문 버튼**과 **용어 사전 검색**
  - 예: 4단계에서 "근저당이 뭐예요?", "앞선 세입자 보증금은 어떻게 알아요?", "집주인에게 뭐라고 물어봐요?"
- 답마다 근거 번호(SOURCES)와 바로 쓸 수 있는 문장(복사), "체크리스트에 표시" 버튼
- 목록에 없는 질문은 "확인할 곳"(HUG 안심전세 앱, 주민센터, 공인중개사) 안내
- AI 대화형 도우미는 확장 방향으로 넘김

### F6. 동네 원룸 시세 (공공데이터, 11/17 완료)

- 국토교통부 **단독/다가구 전월세 신고정보**(공공데이터포털 15126472)로 동네(법정동) 단위 최근 보증금 · 월세 분포를 보여 줌
- 쓰는 곳: **방 상세 "이 방, 안전한가요?"**에서 이 방 보증금 · 월세가 동네 신고 거래와 비교해 어느 정도인지(참고), 2단계 "시세 알아보기"
- 거래가 적으면 0이나 "적정"으로 치지 않고 **"거래 기록이 적어요"**로 보여 줌 (못 읽은 값을 안전으로 치지 않는 원칙과 같음)
- 호출 주소(11/13 실제 호출로 확인): `https://apis.data.go.kr/1613000/RTMSDataSvcSHRent/getRTMSDataSvcSHRent` · 요청 `LAWD_CD`(시군구 코드 5자리) · `DEAL_YMD`(계약 연월 6자리) · 응답 항목 `umdNm`(동) · `deposit`(보증금, 만 원) · `monthlyRent`(월세, 만 원) · `houseType`(단독/다가구) · `totalFloorAr`(면적) · `buildYear` · `contractType`. 예: 마포구 2026년 10월 364건
- API 키는 `.env`의 `DATA_GO_KR_API_KEY`(서버에서만 읽음). 같은 IP는 1분에 20번까지(키 하루 한도 보호), 응답은 CDN에 12시간 저장. 서버로는 지역 코드 · 계약 연월만 보내고 등기부등본은 계속 브라우저 안에서만 처리
- 하지 않는 것: 이 데이터로 판정용 "건물 시세" 자동 계산 (다가구 매매는 거래가 드물고 번지가 일부만 나와 부정확)
- 플랜 B: 키 승인이 늦거나 일정이 밀리면 국토부 실거래가 공개시스템 링크 안내로 대체

## 7. 설계 원칙: 앱 안에서 AI를 부르지 않음

| 역할 | 어떻게 |
| --- | --- |
| 서류에서 항목 읽어 내기 | 규칙 기반 읽기 + 사용자 확인 · 수정 |
| 위험 판정 | 정해진 규칙 |
| 쉬운 말 설명, 질문 · 특약 문장 | 용어 사전 + 상황별 문장 틀 |
| 도우미 (F5) | 단계별 자주 묻는 질문 + 용어 사전 검색 |

**왜 이렇게 하나**
- 과제 조건: 팀 프로젝트용 API 키는 쓸 수 없고, 이 과제는 Claude로 **개발**하는 과제
- 같은 서류면 항상 같은 결과 → 샘플 정답표로 자동 테스트 가능
- 외부 서비스 장애 · 사용 한도와 상관없이 데모가 끊기지 않음
- 등기부등본 내용이 외부 AI 서비스로 나가지 않음 (개인정보 보호)

- 모든 결과 화면에 "참고용 안내이며, 최종 확인은 공인중개사 · 법률 전문가에게" 문구

**필요한 키** (값은 `.env`에만, 환경 변수로만 읽음)

| 이름 | 용도 |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase 프로젝트 주소 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase 공개 키 (브라우저용, 권한은 DB 보안 규칙으로 제한) |
| `DATA_GO_KR_API_KEY` | 공공데이터포털 키 (F6 동네 시세, 서버에서만 읽음) |
| `LAW_API_OC` | 국가법령정보 API (근거 원문 대조, 개발할 때만 씀) |
| `NEXT_PUBLIC_SITE_URL` | 선택. 공유 미리보기 주소(Vercel · Netlify에서는 자동) |

## 8. 사용 흐름 (포스터 · 처음 쓰는 사람 기준)

개인 과제는 시연 없이 포스터로 평가하므로, 포스터와 앱 첫 화면이 같은 흐름을 보여 준다.

1. 포스터 QR → 로비 「이 방, 계약해도 될까?」 → **관심 있는 방 담고 시작하기**
2. 주소 · 보증금 · 월세 3칸 → 방 화면에 **동네 시세**(참고)가 바로 붙음
3. **등기부등본 올려서 점검하기** → 없으면 '떼는 법'을 보거나 샘플로 먼저 해 보기
4. 신호등 + 3줄 요약 → 확인할 것(뜻 · 이유 · 할 일) → 등기부로 알 수 없는 것
5. **다음에 할 일**: 집주인 · 중개사에게 물어볼 말, 특약 문장, 요청 목록, 가족에게 보낼 요약
6. 홈의 방 카드에 신호등과 6단계 진행이 남고, 다음 할 일로 이어짐

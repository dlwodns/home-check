# 홈체크 포스터 만들기

결과물: `poster/homecheck-poster-A2.pdf`(제출 · 인쇄용, 1쪽) · `poster/homecheck-poster-preview.png`(미리보기)

## 1. 먼저 정할 것: 한 문장

지나가는 사람이 **5초 안에** 읽고 기억할 문장 하나를 정하고, 그 문장을 가장 크게 쓴다(#BetterPoster 방식).
지금 문장: **"등기부등본 한 장으로 이 방의 위험과 계약 방법까지, 쉬운 말로"**

## 2. 배치 (A2 세로)

| 구역 | 내용 | 참고 |
| --- | --- | --- |
| 위 띠 (초록) | 아이콘 · **홈체크** · 부제 「이 방, 계약해도 될까?」 · 이름 · 과정 | 학교 DKUG 양식의 머리 띠 |
| 빌보드 (위쪽 약 40%) | 한 문장(가장 큼) · 흐름 칩 4개 · **QR + 주소** · 앱 화면 핵심 **확대** 2장(신호등 판정, 물어볼 말) | #BetterPoster |
| 카드 5장 (3단 + 2단) | ① 문제(대상 · 강한 숫자) ② 핵심 기능(+ 후보 방 화면) ③ 이렇게 달라요 ④ 검증 · 만든 과정(두 칸 너비, 한계 명시) ⑤ 기대 효과 · 다음 | 2025–26 벤토 그리드 |
| 아래 띠 (초록) | 참고용 안내 · 70% · 80%는 참고선 | DKUG 아래 띠 |

- 카드 제목 앞 **■ 초록 네모**는 DKUG 양식의 섹션 표시를 가져온 것
- 색: 초록 `#1f7a4d` 하나가 주인공, 신호등 3색은 신호등에만. 노랑 바탕 · 경고 아이콘 같은 겁주는 분위기는 쓰지 않음
- 글자 크기(1m 거리 기준): 이름 96pt · 한 문장 60pt · 카드 제목 25pt · 본문 16pt 이상 · 작은 글 13pt 이상
- 글꼴: Pretendard(앱과 같음)
- 앱 화면은 휴대폰 전체를 작게 넣지 않는다(A2에서 글자 2mm, 1m에서 못 읽음). 핵심 부분만 잘라 본문 글자가 5mm 이상 되게(`zoom-*.png`)
- 정확도 숫자는 '67%'만 떼어 쓰지 않는다. '처음 보는 서류로 시험 → 틀린 원인 고침 → 60/60' 흐름으로 보여 준다

## 2-1. 과제 공지 (11/23 최종)

- A2 PDF, 인쇄해 전시(시연 없음). 순서 권장: **문제 → 핵심 기능 → 기대사항**(PRD 목차와 비슷하게)
- 파일 이름 `6팀-단국대학교-이재운-홈체크.pdf` → 6팀 공유 드라이브 '개인과제' 폴더
- 카드는 ①–⑥ 번호로 읽는 순서를 정하고, 위 띠에 팀 · 학교 · 이름

## 3. 내용 규칙

- **숫자는 저장소에서 다시 잰 값만**: 테스트 수(`npx vitest run`), 근거 ✅ 개수(`docs/SOURCES.md`), 블라인드 시험(`docs/SCHEDULE.md` A1). 피해 사례는 PRD '근거(실제 사례)'에 있는 것만
- '100% · 완벽 · 안전 보장' 같은 말 금지. '안전'은 "등기부 기준 큰 위험 신호 없음"의 뜻으로만, 알 수 없는 것도 있다고 함께 적기
- 다른 서비스 이름을 깎아내리지 않는다. 비교는 "흔한 방식 vs 홈체크"로
- **수상 포스터에 없는 항목은 넣지 않는다**(11/23 사용자 결정): AI 활용 과정 · 동작 구조도 · 활용 분야 등 채점관 추측이나 학교 안내문에서 온 것은 빼고, 레퍼런스(결론형 헤드라인 · QR · 대표 화면 · 강한 숫자 · 짧은 방법 흐름 · 판단 기준 수)만 따른다
- 검증에 'AI가 만든 시험 서류'처럼 'AI 없이 판정'과 헷갈리는 말을 쓰지 않는다. 가장 큰 한계(실제 PDF 미검증)는 작은 글씨에 묻지 말고 검증 카드에 밝힌다
- **스스로를 깎는 표현 금지**(수상작 공통): '놓침 · 못 한 것 · 가짜 · 지어낸' 대신 '찾아 고친 원인 N가지 · 다음 검증 · 테스트용 가상'. 사실(67–80% 등)은 README · PRD에 그대로 두고 포스터는 확인 가능한 긍정형 사실로. 면책 문구는 아래 띠 한 곳에만
- 피해 사례에는 언론사 · 연도 출처를 붙인다. 숫자는 PRD 원문 표현을 넘지 않게(예: '임대업자 한 명' ≠ '원룸 한 곳')
- 수상 포스터 공통점(11/23 조사): 결론형 큰 헤드라인 + QR, 대표 화면 하나를 크게, 블록 4–5개, 문제는 강한 숫자 하나, 과정은 짧은 흐름도 한 줄
- 화면 캡처에는 **샘플(가짜) 서류**만 쓴다. 실제 등기부 · 개인정보 금지
- 저장소가 비공개면 GitHub 주소는 넣지 않는다(QR은 배포 주소)

## 4. 만드는 순서

1. **화면 캡처** (앱이 바뀌었을 때만): `scripts/poster-shots.mjs` → `poster/img/zoom-*.png`(포스터용 확대) · `screen-*.png`(참고용)
   - playwright-core는 저장소 밖 폴더에 설치하고 `NODE_PATH`로 알려 준다
2. **QR** (주소가 바뀌었을 때만): `poster/img/qr.svg`. 오류 정정 M, 여백 4칸
3. **내용 고치기**: `poster/poster.html` (모든 크기는 mm · pt)
4. **뽑기**: `CHROME_PATH=/경로/chrome node scripts/make-poster.mjs`
   - 이 서버처럼 Pretendard가 시스템에 없으면 Pretendard가 든 폴더를 `FONTCONFIG_FILE`로 알려 준다

## 5. 다 됐다고 하기 전에 확인

- [ ] PDF가 **1쪽, 420 × 594mm** (`/MediaBox [0 0 1191 1684]` 근처)
- [ ] 미리보기 PNG를 눈으로: 글자 넘침 · 카드 잘림 · 숫자가 두 줄로 쪼개짐 · 아래 빈 공간
- [ ] QR을 휴대폰으로 찍어 배포 주소가 열리는지
- [ ] 숫자 3개(테스트 · 근거 · 블라인드)가 저장소 값과 같은지
- [ ] 이름 · 과정 · 날짜
